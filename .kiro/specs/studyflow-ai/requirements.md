# StudyFlow AI — Requirements

**Tagline:** Plan Smarter. Study Better.

StudyFlow AI is an intelligent multi-agent academic assistant that helps college
students manage assignments, exams, study schedules, deadlines and other
commitments. The differentiator is **adaptive agentic planning** (not just a
chatbot or calendar): a LangGraph-orchestrated multi-agent workflow performs task
decomposition, deterministic scheduling, validation, and human-approved dynamic
replanning.

## Glossary

- **Course** — an academic class (e.g. "Machine Learning").
- **Assignment** — a graded deliverable with a due date and estimated effort.
- **Task** — a smaller actionable unit, optionally linked to an assignment.
- **Exam** — a scheduled examination with topics and prep hours.
- **Calendar Event** — a dated item. `kind` ∈ {class, exam, assignment, study, personal, meeting}.
- **Study Block** — a movable calendar event of kind `study`, generated by the scheduling engine, optionally linked to a task/assignment/exam.
- **Fixed Event** — an event (`is_fixed = true`) the engine must not move (classes, exams, meetings, personal).
- **Proposal** — a pending set of schedule changes (added/moved/removed blocks) awaiting human approval.

## User Stories & Acceptance Criteria

### US-1 Manage courses
As a student I can create, view, edit and delete courses.
- AC-1.1 A course has name, code (optional), color, instructor (optional).
- AC-1.2 Deleting a course nulls references from assignments/exams (no orphan crash).

### US-2 Manage assignments
As a student I can create, edit, delete, search, filter, sort and complete assignments.
- AC-2.1 An assignment has title, course, due date, priority (low/medium/high), status (not_started/in_progress/completed), estimated hours, description.
- AC-2.2 List supports search by title and filter by course, status, priority; sort by due date.
- AC-2.3 Marking complete sets status and `completed_at`; progress metrics update.
- AC-2.4 Overview metrics (total, due this week, in progress, completed, high priority) are computed from stored data.

### US-3 Manage tasks
As a student I can create, edit, delete and complete tasks, optionally linked to an assignment.
- AC-3.1 A task has title, optional assignment_id, priority, estimated minutes, deadline, status, order index.
- AC-3.2 Tasks filter by Today / This Week / Overdue / Completed.
- AC-3.3 Generated subtasks preserve the parent assignment relationship.
- AC-3.4 Scheduling uses task estimates without double-counting the parent assignment estimate.

### US-4 Manage exams
As a student I can manage exams and request a distributed prep plan.
- AC-4.1 An exam has course, title, date/time, topics[], estimated prep hours, priority, prep progress.
- AC-4.2 Requesting a study plan distributes prep across available days before the exam.

### US-5 Calendar
As a student I can view and edit a calendar.
- AC-5.1 Weekly and daily views; monthly overview.
- AC-5.2 Add/edit/delete events; events are color-coded by kind.
- AC-5.3 Fixed events are visually distinct from movable study blocks.
- AC-5.4 Conflicts are shown clearly.

### US-6 Dashboard
As a student I see an at-a-glance productivity dashboard.
- AC-6.1 Overview cards: upcoming assignments, upcoming exams, today's study tasks, conflicts resolved — all from live data.
- AC-6.2 Monday–Sunday weekly calendar with week navigation and clickable events.
- AC-6.3 Bottom cards: upcoming deadlines, today's focus tasks, study progress %.
- AC-6.4 Embedded AI assistant panel with suggested actions wired to the agent backend.

### US-7 AI task decomposition
As a student I can ask the AI to break an assignment into tasks.
- AC-7.1 Produces an ordered list of validated subtasks with estimated minutes and priority.
- AC-7.2 Subtasks persist and are linked to the assignment.
- AC-7.3 Works with an LLM when configured, and with a deterministic, clearly-labeled fallback otherwise.

### US-8 Schedule generation
As a student I can generate a conflict-free study schedule.
- AC-8.1 Study blocks never overlap fixed events or each other.
- AC-8.2 Tasks are scheduled before deadlines when feasible, honoring priority.
- AC-8.3 Respects preferred study hours, session length and breaks.
- AC-8.4 Infeasible requests return an explicit shortfall report; no invented slots.

### US-9 Dynamic replanning (core demo)
As a student I can add an unexpected event and ask the AI to replan.
- AC-9.1 The workflow detects the conflict, finds alternative slots, validates, and returns a proposal.
- AC-9.2 A failed validation triggers a bounded retry with the conflict info, else a feasibility warning.
- AC-9.3 The proposal preview shows original vs proposed, added/moved/removed blocks, and per-change explanations.

### US-10 Human-in-the-loop approval
As a student I review and approve/reject proposed changes.
- AC-10.1 No schedule change is applied without approval.
- AC-10.2 Approve applies changes atomically and persists them.
- AC-10.3 Reject discards the proposal with no side effects.
- AC-10.4 After approval, dashboard and calendar reflect the changes (persist after refresh).

### US-11 Agent observability
As a judge/student I can see what the agents did.
- AC-11.1 An Agent Activity panel lists, per run: agent invoked, tools used, current step, validation result, approval required.
- AC-11.2 Activity reflects real executions; nothing is fabricated.

### US-12 Preferences
As a student I can set scheduling preferences.
- AC-12.1 Preferred study start/end hours, session length, break duration, available days, default priority, timezone.
- AC-12.2 Preferences are applied by the scheduling engine.

### US-13 Local demo without secrets
As a user I can run the app locally without any API key.
- AC-13.1 With no LLM key, a clearly-labeled deterministic demo mode powers decomposition and chat.
- AC-13.2 No secrets are committed; `.env.example` documents configuration.

## Non-Functional

- NFR-1 All timestamps stored in UTC (ISO-8601); client renders in the user's timezone.
- NFR-2 REST APIs typed with Pydantic, documented via OpenAPI, consistent errors.
- NFR-3 Deterministic validation independent of the LLM for all scheduling math.
- NFR-4 Responsive layouts (desktop/tablet/mobile).
- NFR-5 Pytest backend tests incl. a smoke test for the replanning demo.
